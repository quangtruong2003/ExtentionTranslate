# TOEIC Part 5 Quiz — Design Spec

**Date:** 2026-08-20
**Status:** Draft — pending user review

## 1. Overview

A new opt-in feature that periodically interrupts the user's browsing with a
TOEIC Part 5 (Incomplete Sentences) quiz. Questions are generated by the AI
(OpenRouter) and prefetched before the quiz appears. The quiz is a full-screen,
non-dismissible overlay that forces the user to answer every question and read
the explanations before closing.

The feature is controlled entirely from the Settings page and reuses the
existing OpenRouter API key and model configuration.

## 2. Settings

A new **"TOEIC Quiz"** section is added to the Settings page.

| Setting | Type | Default | Notes |
|---|---|---|---|
| `toeicQuizEnabled` | boolean | `false` | Master on/off toggle |
| `toeicQuizIntervalMinutes` | number | `15` | Accumulated active-screen minutes before a quiz triggers. Range 5–120. |
| `toeicQuizQuestionCount` | number | `5` | Questions per quiz. Range 3–20. |

Time per question is **fixed at 30 seconds** and is not user-configurable.
Total quiz time = `questionCount × 30s`.

These three fields are added to `ExtensionSettings`, `DEFAULT_SETTINGS`,
`normalizeSettings`, and the settings storage layer. They are **not** part of
`PopupSettings` (the dictionary popup does not need them).

## 3. Timer & Trigger (background service worker)

### Accumulation
- A `chrome.alarms` alarm fires **every 1 minute** while the feature is enabled.
- On each tick the worker calls `chrome.idle.queryState(60)`. If the state is
  `"active"`, it adds 1 minute to an accumulated counter stored in
  `chrome.storage.session` (resets automatically when the browser closes, which
  matches the "per browsing session" requirement).
- Idle/locked time does **not** count.

### Prefetch
- When accumulated time first reaches **80%** of the configured interval and no
  question set is cached yet, the worker calls the AI to generate the questions
  (see §4) and caches the parsed result in memory.
- If the prefetch fails, it is retried on the next alarm tick.

### Trigger
- When accumulated time reaches **100%**, the worker:
  1. Finds the focused window's active tab.
  2. Skips tabs where a content script cannot run (`chrome://`, `chrome-extension://`,
     Web Store, DevTools, etc.) and waits for the next tick.
  3. Sends a `SHOW_TOEIC_QUIZ` message to the content script with the cached
     question payload.
- If no cached questions exist at trigger time (prefetch failed), the worker
  generates them synchronously before sending, showing a brief loading state in
  the overlay.

### Reset
- After the quiz is closed (completed or timed out), the content script reports
  back and the worker resets the accumulated counter to `0`.

### Manifest changes
Add `"idle"` and `"alarms"` to `permissions`.

## 4. Question Generation (AI)

A single non-streaming OpenRouter call returns the full quiz as JSON.

### Request
- Uses the configured API key, model, and `targetLanguage`.
- Thinking/reasoning is **disabled** for this call to reduce latency and cost.
- `response_format: { type: "json_object" }` is requested.

### System prompt
Based on the user-provided TOEIC Part 5 generator prompt, with these additions:
- `QUESTION_COUNT` is substituted with the configured count.
- The model must return **strict JSON** matching the schema below.
- `explanation` and `relatedKnowledge` are written in the user's
  `targetLanguage` (vi / en / zh-CN).
- The self-check checklist from the original prompt is retained.

### Response schema
```json
{
  "questions": [
    {
      "id": 1,
      "text": "The company plans to ______ its operations...",
      "options": ["expansion", "expansive", "expand", "expanded"],
      "correctIndex": 2,
      "explanation": "Sau 'to' cần động từ nguyên mẫu...",
      "relatedKnowledge": "Cấu trúc: plan to + V-inf..."
    }
  ]
}
```

### Parsing & validation
- Strip markdown code fences if present, then `JSON.parse`.
- Validate: correct question count, each question has exactly 4 options,
  `correctIndex` is 0–3, all text fields non-empty.
- On any validation failure, retry once. If it still fails, skip this quiz
  cycle: show an error toast and reset the accumulated timer so the next
  attempt happens after another full interval.

## 5. Quiz UI (content script overlay)

Rendered in the **existing Shadow DOM host** as a separate full-screen overlay,
independent of the dictionary popup.

### Layout
- Fixed full-viewport backdrop (`position: fixed; inset: 0`) with a
  semi-transparent dark background that blocks scroll and clicks on the page.
- A centered card holds the quiz. No close/dismiss button is present while the
  quiz is in progress.

### Answering phase (stepper)
- One question at a time with a progress indicator (`3/10`) and a countdown of
  the **total remaining time**.
- Four option buttons (A/B/C/D). Selecting one highlights it.
- A "Câu tiếp theo" button advances. The last question shows "Xem kết quả".
- Selecting an answer is required before advancing.
- No per-question feedback is shown during this phase.

### Timeout
- When the total countdown reaches zero, the quiz auto-submits: answered
  questions are graded, unanswered questions count as incorrect. Control moves
  straight to the results phase.

## 6. Results phase

- A scrollable list shows **every** question in order:
  - Correct → green check, the chosen answer, and the explanation + related
    knowledge.
  - Incorrect → red cross, the chosen answer, the correct answer, and the
    explanation of why the choice was wrong + related knowledge.
  - Unanswered (timed out) → marked as incorrect with the correct answer shown.
- The **"Đóng"** button sits at the bottom and is **disabled** until the user
  scrolls the results container to the bottom (a "Đã đọc xong" affordance at the
  end also enables it as a fallback).
- Clicking "Đóng" dismisses the overlay and notifies the background to reset the
  timer.

## 7. Edge cases

- **Feature toggled off mid-session:** the alarm is cleared and any pending
  prefetch/trigger is cancelled.
- **No API key:** the quiz cannot generate questions; the feature toggle is
  allowed but a trigger attempt shows an error toast and resets the timer.
- **Tab closed during quiz:** the overlay is destroyed with the tab; the
  background resets the timer on the next tick when it detects no active quiz.
- **Browser restart:** `chrome.storage.session` clears, so the accumulated time
  resets naturally.
- **Multiple windows:** only the focused window's active tab receives the quiz.

  trigger message flow.
